## Features

### ✅ Day Counter HUD

**Files:** `ui/day_hud.gd` (new), `ui/day_hud.tscn` (new), `autoload/scene_manager.gd`, `world/field.gd`, `world/town.gd`

Replace the bare `$DayLabel` node in `field.tscn` and `town.tscn` with a proper CanvasLayer HUD element styled to match the existing parchment palette (health bar, scripts HUD). Add a `day_updated` signal to `SceneManager` so the HUD reacts reactively rather than polling.

---

### ✅ Always-Visible NPC Name Labels

**Files:** `npc/npc_base.gd`

NPC name labels are currently only shown when the player enters detection range. Change all NPC and villager name labels to be visible at all times. The `[A] Talk` prompt label remains proximity-gated.

---

### ✅ Villager Name Generation

**Files:** `pipeline/world_gen.py`, `world/town.gd`, `npc/npc_base.gd`

Wandering villagers currently display the placeholder name "Villager". During world generation, the LLM produces a pool of 20 fantasy names stored in `world_registry.json` under `thornwall.villager_names`. On town load, `town.gd` shuffles the pool and assigns names to all wanderer nodes in the `"wanderer"` group.

---

### ✅ Up Idle Animation Bug Fix

**Files:** `npc/npc_base.gd`, `Player/player.gd`

The `idle_up` animation either references an undefined animation or contains transparent/invisible trailing frames from the spritesheet. Audit the frame count for `ROW_UP` in the swordsman sprite sheet and trim to non-transparent frames. Add a proper `idle_up` animation to wanderers and use it when moving upward.

---

### ✅ Boundary Enforcement for Villagers and Slimes

**Files:** `npc/npc_base.gd`, `mob/slime1.gd`, `mob/slime1_boss.gd`

Wandering villagers currently move without boundary clamping and can leave the playable area. `BoundaryLeft`, `BoundaryRight`, `BoundaryTop`, and `BoundaryBottom` nodes are already placed in the scenes. On `_ready()`, read their positions to compute a `Rect2 _world_bounds` and clamp villager position in `_process()` after each movement step. When a boundary is hit, flip the direction component and pick a new wander direction. Verify slime boundary clamp values match the visual boundary rects.

---

### ✅ Villager Background Conversations (Speech Bubbles)

**Files:** `npc/npc_base.gd`, `ui/speech_bubble.gd` (new), `pipeline/end_of_day.py`, `pipeline/world_gen.py`

When two wandering villagers come within ~60 px of each other and neither is on cooldown, they pause and exchange a brief ambient conversation. A speech bubble (rounded dark parchment label above the NPC's head) shows one line each, then both resume wandering. Each participant has a **30-second cooldown** before they can begin another conversation.

Conversation lines are LLM-generated: `end_of_day.py` produces a pool of ~10 two-line exchanges per day in `dialogue/villager_ambient_day{N}.json`, incorporating current rumors and kill context. Day 1 exchanges are generated by `world_gen.py` as part of initial world setup.

---

### ✅ Day Cycle Loading Bar

**Files:** `autoload/scene_manager.gd`, `pipeline/end_of_day.py`

Replace the animated-dots overlay during the day cycle pipeline with a progress bar that tracks per-NPC JSON generation. `end_of_day.py` writes `pipeline_progress.json` before the NPC loop and updates it after each NPC is completed (including fallback cases). Godot polls the file each tick and animates the bar fill.

Includes improved error diagnostics: on timeout, the overlay reports which NPC was last being processed. Each NPC call in `end_of_day.py` has an individual 90-second timeout via `concurrent.futures`; a timed-out NPC falls back to previous dialogue and the pipeline continues rather than hanging until Godot's global 180-second timeout fires.

---

### ✅ Main Menu + In-Game Pause Menu

**Files:** `ui/main_menu.gd` (new), `ui/main_menu.tscn` (new), `ui/pause_menu.gd` (new), `ui/pause_menu.tscn` (new), `autoload/scene_manager.gd`, `Player/player_input.gd`, `world/field.gd`, `world/town.gd`, `project.godot`

**Main menu** (startup scene): Title screen with buttons — **New Game**, **Continue** (load slot 0, disabled with no save), **Load** (slot picker for slots 0–2). New Game runs `world_gen.py` as a blocking subprocess with a progress overlay before entering the world.

**In-game pause menu**: `Escape` / `Start` button (new `PlayerInput.PAUSE` constant) pauses the scene tree and opens a CanvasLayer overlay (layer 250) with **Resume**, **Save**, and **Load** options.

**Save system** added to `SceneManager`: `save_game(slot)`, `load_game(slot)`, `has_save(slot)` — serialises/deserialises full game state to `save_{slot}.json` including current scene path.

---

## Dependency Notes

- **Villager Name Generation** must be complete before **Villager Background Conversations** (conversations use assigned names in bubble headers).
- **Boundary Enforcement** should be complete before **Villager Background Conversations** (wanderers need bounded movement before proximity logic is meaningful).
- **Main Menu** depends on the **Save System** within SceneManager.
- **Day Cycle Loading Bar** is independent of all other items.
